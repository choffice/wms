# Phase 3.4 — 업무 잔여 예상시간

## 목적

진행률 자체를 성과지표로 사용하지 않는다.

관리자는 최종 수행 로케이션을 보고 실제 진행상황을 판단한다.

진행률은:

> 현재 마지막 수행 위치가 해당 구역 전체 활성 Leaf 중 어느 지점에 있는가

를 간단히 숫자로 나타내는 참고값이다.

## 예상시간의 목적

업무 배정 시 관리자가 다음을 판단할 수 있도록 한다.

- 현재 구역이 어디까지 진행되었는가
- 같은 구역 / 같은 업무가 과거에 어느 정도 속도로 수행되었는가
- 지금 위치부터 구역 끝까지 계속 수행한다면 대략 몇 시간이 필요한가
- 특정 시작 로케이션으로 새 배정을 만들면 그 시작점부터 얼마나 걸릴 것으로 보이는가

자동 우선순위는 만들지 않는다.

## 계산 데이터

정확히 같은:

```text
Area + WorkType
```

조합의 과거 Assignment만 사용한다.

Historical Sample 조건:

- Assignment 상태가 COMPLETED
- 실제 마지막 수행 로케이션 존재
- WorkSession 존재
- 모든 WorkSession 종료 완료
- 모든 WorkSession qualityStatus = NORMAL
- 실제 작업시간 > 0

UNCERTAIN 세션이 섞인 Assignment는 예상시간 학습 표본에서 제외한다.

## 부분 작업도 표본으로 사용

Assignment에는 endLocation이 없으므로
과거 작업이 구역 전체를 끝낸 경우만 기다리지 않는다.

예:

```text
A01 전체 Leaf = 100개
Assignment A: 10번 ~ 29번, 실제시간 60분
Assignment B: 30번 ~ 59번, 실제시간 80분
```

각 Assignment가 실제로 수행한 구간 비율을 계산하고
실제 작업시간을 해당 비율로 환산한다.

개념적으로:

```text
구역 전체 환산시간
= 정상 실제 작업시간 합
  / 실제 수행 구간 비율 합
```

예상 잔여시간:

```text
구역 전체 환산시간 × 현재 남은 구역 비율
```

선택 시작점 예상시간:

```text
구역 전체 환산시간 × 선택 시작점부터 끝까지의 구역 비율
```

## 진행률 정의

기존처럼 Assignment 시작점을 0%로 다시 잡지 않는다.

현재 진행률은 **구역 전체 기준 위치 퍼센트**이다.

예:

```text
A01 Leaf 100개
시작점 = 61번째
마지막 수행 = 72번째

현재 구역 위치 = 약 72%
```

이번 Assignment 자체가 12개를 수행했다고 해서
`12 / 40 = 30%`처럼 표시하지 않는다.

## UI

관리자 Dashboard 로케이션 업무 현황:

- 구역 위치 %
- 마지막 수행 로케이션
- 예상 잔여시간
- Historical Sample 수
- 마지막 수행자 / 시각

업무배정 화면:

- 현재 구역 위치
- 현재점 기준 예상 잔여
- 관리자가 선택한 시작점 기준 예상시간
- 동일 구역·업무 Historical Sample 수
- 구역 전체 환산 평균시간

시간은 UI에서 과도한 정밀도를 피하기 위해 약 10분 단위로 표시한다.

예:

```text
약 2시간 20분
```

## 데이터가 없을 때

같은 Area + WorkType의 정상 완료 이력이 0건이면:

```text
이력 부족
```

으로 표시한다.

다른 구역이나 다른 WorkType의 평균으로 자동 대체하지 않는다.
