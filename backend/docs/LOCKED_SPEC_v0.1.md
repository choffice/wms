# 물류센터 근무자 관리·업무배정 시스템
## 기능/기술 잠금 명세 v0.1

> 목적: 입사 제출용 포트폴리오 프로젝트  
> 방향: 물류센터에서 MATE·PDA·로케이션·업무배정·진행기록·특이사항·로그를 통합 관리하고, 실제 작업 이력과 소요시간 데이터를 다음 업무배정의 참고자료로 활용하는 시스템

---

## 1. 프로젝트 핵심 목적

이 프로젝트는 단순한 CRUD 업무관리 시스템이 아니라 다음 데이터를 축적하는 것을 핵심으로 한다.

- 누가 어떤 PDA를 사용했는가
- 누가 어떤 업무를 수행했는가
- 어떤 구역에서 어디까지 실제 작업했는가
- 해당 로케이션을 마지막으로 수행한 사람과 시각은 언제인가
- 특정 업무에 실제로 얼마만큼의 시간이 소요되었는가
- 구역별 업무 진행률은 어느 정도인가
- 특이사항과 업무처리 이력이 어떻게 연결되는가

관리자가 지정한 업무는 **완수 범위가 아니라 업무의 시작점과 대상 구역을 지정하는 배정**이다.

따라서 다음 두 개념을 반드시 분리한다.

- **관리자 배정 정보**
- **MATE 실제 수행 정보**

# 4. 사용자 역할

역할은 두 종류만 사용한다.

- `ADMIN`
- `MATE`

중간관리자, 서버관리자 등 별도 역할은 현재 프로젝트 범위에서 제외한다.

---

# 5. 계정 / 사원번호

## 관리자
- 사원번호 Prefix: `AD`
- 예: `AD0001`, `AD0002`

## MATE
- 사원번호 Prefix: `MT`
- 예: `MT0001`, `MT0002`

## 생성 규칙
- 역할별 Prefix + 자동 증가 번호
- 관리자가 등록할 때 서버에서 자동 생성
- 중복 불가
- 생성 후 변경 불가
- 한 번 발급된 번호는 다른 사람에게 재사용하지 않음

DB 내부 PK와 사용자에게 노출되는 사원번호는 별도로 관리한다.

예:

```text
Mate.id = 37
employeeNo = MT0028
```

# 6. MATE 정보

설정에서 관리 가능한 기본 정보:

- 이름 (필수)
- 별명
- 근무스케줄
  - 평일 / 주말
  - 요일
  - 주간 / 마감

## 이름과 별명

- 이름은 DB상의 정식 정보
- 실제 현장 확인용 표시는 별명을 우선 사용
- 별명은 관리자가 지정
- 팀 / 직책 구분은 두지 않으며 역할은 모두 MATE로 통일

## 퇴사 / 재입사

- 퇴사 시 삭제하지 않고 비활성 처리
- 과거 업무 및 PDA 사용 이력 보존
- 일정 기간 정보를 유지
- 재입사 시 기존 MATE 정보를 다시 활성화하는 방향을 우선 고려

# 7. MATE 상태 / 거소

상태 Enum:

```text
AVAILABLE
WORKING
BREAK
AWAY
OFF_DUTY
```

의미:

| 상태 | 의미 |
|---|---|
| AVAILABLE | 근무 중이지만 현재 업무 없음 |
| WORKING | 업무 수행 중 |
| BREAK | 휴게 |
| AWAY | 장시간 자리 비움 |
| OFF_DUTY | 근무시간 종료 |

거소는 상태와 별도로 관리한다.

기본 선택 예:

- 휴게실
- 식사
- 사무실
- 창고
- 기타 직접입력

관리자 현황판에서는 예를 들어 다음처럼 표현 가능하다.

```text
민수 / PDA 12 / 재고실사 / A01-13-24
지현 / PDA 08 / 휴게 / 휴게실
현우 / PDA 03 / 자리비움 / 사무실
서연 / PDA 14 / 대기
```

# 8. PDA 관리

PDA는 모의 화면이지만 개념상 실제 하드웨어 기기 단위로 관리한다.

## PDA 등록정보

- 내부 PK
- PDA 번호
- 상태
- 활성 여부

PDA 번호는 중복 불가.

## PDA 상태

```text
AVAILABLE
IN_USE
LOST
INSPECTION
RETIRED
```

## 핵심 원칙

**PDA 기기 자체의 PK와 현장에서 보이는 PDA 번호를 분리한다.**

예:

```text
id = 17
deviceNumber = 32
```

PDA 번호를 32번에서 41번으로 변경해도 과거 이력은 `device_id = 17`을 참조한다.

따라서 번호 변경 후에도 해당 기기의 이력은 유지된다.

## PDA 번호 맞교환

관리자 메뉴에서 두 기기를 선택하여 번호를 서로 교체하는 기능을 둔다.

예:

```text
기기 id 17 / PDA 32
기기 id 29 / PDA 41

↓ 교체

기기 id 17 / PDA 41
기기 id 29 / PDA 32
```

트랜잭션 단위 Service 로직으로 처리한다.

## PDA 삭제

- 사용하지 않는 번호는 삭제 가능
- 신규 번호 추가 가능
- 과거 사용이력이 존재하는 실제 기기는 물리삭제보다 `RETIRED` 처리 우선
- 단순 오등록 등 이력이 없는 기기는 삭제 가능

---

# 9. PDA 로그인 / 사용 관계

실제 PDA 하드웨어를 연결하지 않으므로 개발/시연 모드에서 모바일로 접속한다.

로그인 흐름:

1. 서버에 등록된 PDA 번호를 드롭다운에서 선택
2. 사원번호 입력
3. 비밀번호 입력
4. 로그인

규칙:

- 한 PDA에는 동시에 한 MATE만 로그인 가능
- MATE는 로그아웃 또는 PDA 반납 후 다른 PDA를 선택 가능
- PDA 할당 / 반납 이력은 반드시 저장

PDA 이력은 다음 목적에 사용한다.

- 누가 어떤 기기를 사용했는지 추적
- PDA 분실 시 마지막 사용자 확인
- 업무 수행과 당시 사용 PDA 연결
- 인수인계 확인

# 10. 로케이션 구조

로케이션은 고정 4단계가 아니라 **가변 깊이 계층형 구조**다.

예:

```text
A01
A01-13
A01-13-24
A01-13-24-05
```

가능한 확장:

```text
A01-13-24
→ A01-14-01
```

또는

```text
A01-13-24
→ A01-13-24-05
```

이 두 경우는 서로 다르다.

- 같은 단계의 번호 범위 확장
- 기존 로케이션 아래에 새로운 하위 단계 추가

따라서 설정 메뉴에서도 두 개념을 구분한다.

## Location 기본 구조

- `id`
- `parentId`
- `segment`
- `fullCode`
- `depth`
- `active`

`fullCode`는 UNIQUE.

정렬은 전체 코드 문자열 순서를 사용한다.

- 종료점
- 층수
- 식품 / 비식품

비식품 선택 시 등록 가능 분류:

세부 구현 시 현재 계층형 Location 구조에 맞게 설정 모델을 조정한다.

# 12. 업무 종류

설정에서 관리한다.

기본 항목:

- 업무명
- 업무 설명(간략)

예:

- 재고실사
- 유통기한 확인
- 로케이션 이동

업무 종류는 과거 기록 보존을 위해 삭제보다 비활성 상태를 지원한다.

---

# 13. 업무배정의 핵심 원칙

관리자는 **완수 범위를 지정하지 않는다.**

예:

```text
"B구역 재고실사 해주세요."
```

시스템상 저장되는 것은:

- 업무 종류
- 대상 구역
- 시작 로케이션
- 담당 MATE

뿐이다.

**종료 로케이션은 관리자가 정하지 않는다.**

실제 어디까지 수행했는지는 MATE의 진행기록에서 결정된다.

---

# 14. 업무 시작점

관리자는 시작점만 지정한다.

예:

- 이전에 마지막 수행된 자리 다음부터 시작
- 수행 주기가 오래되었다고 판단해 구역 처음부터 시작

시스템이 현장 체크 주기를 자동 계산하여 업무 우선순위를 강제하지 않는다.

---

# 15. 동일 업무 / 트레이드

기본 원칙:

- 동일 업무를 여러 MATE가 동시에 수행하는 구조는 기본적으로 사용하지 않음
- 이미 배정된 업무는 MATE 간 트레이드 / 재배정 가능

트레이드 및 재배정 이력은 별도로 저장한다.

---

# 16. 업무 진행 구조

업무시간은 **업무가 배정된 시각부터가 아니라 MATE가 [시작]을 누른 시점부터** 측정한다.

기본 흐름:

```text
관리자 업무배정
→ MATE 배정업무 확인
→ 시작
→ 작업
→ 진행기록
→ 일시정지 / 재개 가능
→ MATE 기준 완료
```

관리자 배정 범위와 실제 수행 범위는 서로 다를 수 있으며 이것이 정상이다.

---

# 17. 진행기록

MATE는 매번 모든 로케이션을 체크하지 않는다.

**마지막으로 실제 수행 완료한 로케이션만 입력한다.**

예:

기존 마지막 완료:

```text
A01-03-02-01
```

새 입력:

```text
A01-07-02-13
```

시스템이 자동 계산:

- 이번 수행범위
- 누적 수행범위
- 현재 마지막 완료 로케이션

진행기록에는 실제로 수행한 위치만 입력해야 한다.

---

# 18. 진행기록 수정

진행기록 수정 가능.

사용자 관점에서는 새 값을 저장하면 현재 값이 덮어쓰기 된다.

하지만 DB 이력은 삭제하지 않는다.

예:

```text
15:20 A01-13-18까지 기록

↓ 정정

15:23 A01-13-16까지 기록
사유: 위치 오입력
```

현재 화면에서는 `A01-13-16`이 표시되지만 이전 기록은 History에 남는다.

수정 사유는 선택 입력.

완료된 Assignment의 진행기록도 동일하게 수정 가능하다.

업무 자체를 진행중 상태로 되돌리는 것이 아니라 **기록을 정정하는 것**이다.

---

# 19. 업무 완료 의미

이 시스템에서 완료는 **관리자가 지정한 전체 범위를 완수했다는 뜻이 아니다.**

업무에는 관리자가 정한 종료범위가 없기 때문이다.

완료는 MATE 중심으로:

> 현재 작업을 여기까지 수행하고 종료했다.

라는 의미다.

종료된 Assignment에는 실제 마지막 수행 로케이션과 작업시간 기록이 남는다.

---

# 20. 동시 작업 제한

한 MATE는 동시에 두 업무를 진행할 수 없다.

다른 업무를 시작하려면 현재 진행 중 업무의 활성 작업 세션을 먼저 종료 또는 일시정지해야 한다.

---

# 21. 일시정지

일시정지는 다음과 같은 실제 비작업 시간을 의미한다.

- 장시간 자리 비움
- 휴식
- 다른 용무 수행

일시정지 시간은 업무 작업시간 통계에서 제외한다.

예:

```text
13:00 작업 시작
14:10 일시정지
14:40 재개
16:00 작업 종료
```

실제 작업시간:

```text
13:00~14:10
+
14:40~16:00
```

---

# 22. WorkSession 원칙

연속된 실제 작업 구간 하나를 WorkSession 한 건으로 본다.

예:

```text
Session #1
13:00 ~ 14:10

Session #2
14:40 ~ 16:00
```

주요 데이터:

- 업무
- MATE
- 당시 PDA 사용 이력
- 시작시각
- 종료시각
- 종료사유
- 마지막 heartbeat
- 데이터 신뢰도 상태

---

# 23. 작업시간 수정 정책

작업시간은 출결 정보가 아니라 **업무 통계 데이터**다.

따라서 관리자가 작업시간을 임의 수정하지 않는다.

목적:

- 업무별 실제 평균 소요시간 분석
- 구역별 평균 작업시간 분석
- 향후 배정 범위 판단에 활용

관리자 수정으로 데이터를 보정하면 통계의 정확성이 떨어질 수 있으므로 원본을 유지한다.

---

# 24. 네트워크 이상 / 비정상 세션

종료 버튼 누락이나 네트워크 오류로 데이터가 오염될 가능성이 있으므로 heartbeat 기반 보조 검증을 사용한다.

예:

```text
13:00 작업 시작
13:02 정상
13:04 정상
13:06 정상
13:08 이후 통신 없음
```

정상 종료 요청이 없거나 통신이 비정상적으로 끊긴 세션은 다음과 같이 표시할 수 있다.

```text
qualityStatus = UNCERTAIN
```

원칙:

- 원본 시간을 관리자가 임의 수정하지 않음
- 정상 기록과 불확실 기록을 구분
- 통계에서 불확실 기록 포함/제외 가능하도록 설계
- 자동 근무종료가 가능한 경우 스케줄 종료시각을 안전장치로 활용

비정상 세션의 세부 자동종료 기준은 구현 단계에서 확정한다.

---

# 25. 근무스케줄

MATE 기본 스케줄:

- 평일 / 주말
- 요일
- 주간 / 마감
- 시작시간
- 종료시간

기본 근무 종료시각이 되면:

- 근무 상태 종료
- 현재 활성 작업 세션 자동 종료

---

# 26. 기간별 예외 근무시간

관리자는 특정 기간에 별도의 근무시간을 지정할 수 있다.

예:

```text
기본
월~금 / 주간

예외
2026-09-01 ~ 2026-09-05
12:00 ~ 21:00
```

기간별 관리자 지정 스케줄이 기본 고정 스케줄보다 우선한다.

---

# 27. 연장

MATE 또는 관리자가 연장을 활성화할 수 있다.

별도 승인 대기 없음.

연장을 누른 순간부터:

- 기본 자동 종료 적용 안 함
- 사용자가 직접 종료할 때까지 유지

즉 고정 30분 / 1시간 추가 방식이 아니다.

---

# 28. 근무 종료 / 로그아웃

진행 중인 작업이 있는 상태에서 근무종료 또는 로그아웃 시 확인한다.

예:

```text
현재 작업을 종료하시겠습니까?
```

기획상 의미는:

- 현재 WorkSession 종료
- 마지막 실제 수행 위치 저장
- 업무에 별도의 `중단` 상태를 만들지는 않음

관리자 배정 자체는 완수과제가 아니므로 `중단`이라는 업무 상태가 필요하지 않다.

---

# 29. 관리자 로케이션 현황

관리자 화면에서는 다음과 같은 구역 단위로 현황을 본다.

예:

```text
A01
A02
B01
B02
```

각 구역에 표시할 주요 정보:

- 마지막 수행 로케이션
- 마지막 수행일시
- 마지막 담당 MATE
- 구역 진행률

시스템이 자동으로 현장의 체크 주기를 판단하여 우선순위를 결정하지 않는다.

업무 수행 주기는 관리자가 현장 기준에 따라 판단한다.

---

# 30. 업무 소요시간 통계

핵심 통계 중 하나.

데이터가 쌓이면 다음을 분석 가능하게 한다.

- 업무 종류별 평균 작업시간
- 구역별 평균 작업시간
- MATE별 실제 작업시간
- 로케이션별 작업 소요시간
- 일정 시간 안에 평균적으로 처리 가능한 범위

예:

```text
재고실사 B구역
평균 2시간 10분

현재 MATE 남은 근무시간
약 1시간 30분
```

관리자가 다음 업무배정 범위를 판단하는 참고자료로 사용한다.

자동 배정을 강제하는 시스템은 아니다.

# 33. 사용 로그

메인 화면에는 최신 로그만 표시한다.

- 화면 로딩 최대 최신 10건
- 전체 로그는 DB에 누적
- UI의 `로그 전체 삭제`는 현재 화면에 표시된 로그를 비우는 동작으로 구분

주요 이벤트 예:

```text
24-07-18 13:17 [특이사항] (메이트→관리자) 재고확인 요청
24-07-18 14:28 [요청해결] (관리자→메이트) 재고수정 완료
24-10-03 14:18 [업무보고] (메이트→관리자) 재고실사:B02 완료
24-10-02 13:33 [업무배정] (관리자→메이트) 로케이션 이동:B03
```

단순 문자열만 저장하지 않고 관련 Entity 참조를 보존한다.

# 34. 업무배정 트레이드 / 재배정 이력

업무의 현재 담당자는 변경될 수 있다.

따라서 현재 값과 별도로 Assignment History를 유지한다.

예:

```text
13:00 관리자 → 정민 배정
14:20 정민 → 현수 TRADE
```

실제 작업시간은 WorkSession마다 MATE를 저장하므로 동일 Assignment에서도:

```text
정민 63분
현수 87분
```

처럼 담당자별 작업시간을 구분할 수 있다.

# 39. 프로젝트에서 특히 지켜야 할 설계 원칙

### 1. 배정과 수행을 혼동하지 않는다.

```text
관리자:
어디에서 어떤 업무를 시작할지 지정

MATE:
실제로 어디까지 수행했는지 기록
```

### 2. 현재값과 이력을 분리한다.

현재 화면은 최신값을 빠르게 보여주되 과거 변경 데이터는 삭제하지 않는다.

### 3. 작업시간은 원본 통계 데이터다.

관리자가 편의상 임의 수정하지 않는다.

### 4. 사람이 보는 번호와 DB 식별자를 분리한다.

대표 사례:

```text
PDA 내부 PK != PDA 표시 번호
Mate 내부 PK != employeeNo
```

### 5. 삭제보다 비활성화를 우선한다.

과거 업무와 로그의 참조 무결성을 유지한다.

### 6. 자동화는 보조수단으로 둔다.

이 시스템은 관리자의 현장 판단을 대체하는 자동 업무배정 시스템이 아니다.

마지막 수행일, 진행률, 평균 작업시간 등의 데이터를 제공하여 관리자의 판단을 돕는 시스템이다.
